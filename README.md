# grandMA1 Patcher

Browser app to edit the DMX patch of grandMA1 (v6.x) show files. No server: it is a static Next.js
export, show files are read and written in the browser only.

**Live: https://kellertobias.github.io/gma1-patcher/**

- Open an existing show from its `name.tar.gz` (the `name.sho` is optional — it is rebuilt from the
  archive), start a new empty show (generated by the app), or start from a console blank template.
- Edit fixture IDs, channel IDs, names and DMX addresses; unpatch fixtures.
- **Export the show as an MVR** scene with an embedded GDTF per fixture type (for visualizers,
  Vectorworks, grandMA3, …).
- **Load GDTF files directly** (no MVR needed) to add their fixture types to the show, or download
  them as grandMA1 fixture-library files (`_FIXTURETYPE .TXT`) for import on the console. Edit the
  name/short name first.
- **Create fixture types from GDTF** and add fixtures of them, or of any type already in the show.
- Import an MVR: fixtures whose fixture ID exists are re-addressed, the others are added. Each GDTF
  type/mode is mapped to a grandMA1 fixture type — or a new type is generated from the GDTF; the DMX
  footprints are compared.
- Generate the show again (`.sho` + `.tar.gz`, optionally zipped).

## How it works

- **Fixture types** are written into the `fixturetypes` pool. A generated type has one coarse channel
  per GDTF DMX channel (plus a fine channel per extra offset), each linked by name to an attribute in
  the show's `pretyp` pool (PAN, TILT, DIM, RED…). The codec round-trips every factory type byte for
  byte (verified against the demo shows), so unchanged types are rewritten identically.
- **The empty show** is assembled entirely by the app: `pretyp` (the standard attribute vocabulary)
  is regenerated from a table, the content pools (fixtures, DMX, groups, presets, cues, effects,
  views) are written empty, and small device/config records are the factory defaults. It contains no
  show content. **It has not been verified on real hardware** — load it once in grandMA onPC before
  relying on it; the "blank show from your console" path is the guaranteed alternative.

## Limits

- Existing fixtures keep their order: cues, presets and groups refer to channels by position, so
  new fixtures are only appended to the last layer or to new layers, and "delete" on an existing
  fixture means unpatch.
- Generated fixture types cover the DMX footprint and attribute links (so the patch is correct);
  photometric data, gel/gobo wheels and channel functions are minimal.
- The file format was reverse engineered (see `docs/FORMAT.md`). Always load a generated show in
  grandMA onPC or on the console and check it before using it in a production.

## Development

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # unit tests; the demo-show tests need GMA1_SAMPLES (see below)
npm run build    # static site in out/
```

The show-file tests use a set of grandMA1 factory demo shows, which are not part of this repository.
Point `GMA1_SAMPLES` at a folder containing them (each as `<name>.sho` + `<name>.tar.gz`).

Code: `src/lib/gma1` (show format: tar/gzip, object tree, records, rules, editable document and
builder, fixture-type codec, GDTF→type builder, grandMA1 fixture-file exporter, empty-show loader),
`src/lib/mvr` (MVR/GDTF parsing and import), `src/components` (UI).

## Deployment

The site is served from GitHub Pages on the `gh-pages` branch (built with
`NEXT_PUBLIC_BASE_PATH=/gma1-patcher`). `docs/github-pages-workflow.yml` is a ready-made GitHub
Actions workflow that rebuilds and deploys on every push to `main`; move it to
`.github/workflows/deploy.yml` and set Pages' source to "GitHub Actions" to enable auto-deploy
(pushing a file under `.github/workflows/` needs a token with the `workflow` scope). Until then,
redeploy manually by rebuilding and pushing `out/` to the `gh-pages` branch.
